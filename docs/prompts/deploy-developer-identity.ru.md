# Промпт для Codex: проверка и развёртывание Developer Identity

Работай в репозитории `C:\dev\ZZClient-10.8.7` (`kernelsyv/kernet`). В проекте уже должна быть система KernelNet Identity: клиентский компонент `CDeveloperIdentity`, VPS-сервис в `services/developer_identity`, корневые Ed25519-сертификаты ролей через Monocypher и значки developer/tester/supporter в nameplates/scoreboard.

Твоя задача: проверить реализацию целиком, исправить найденные ошибки, настроить клиент под мой HTTPS endpoint, развернуть сервис на моей VPS и опубликовать изменения в GitHub отдельной веткой и draft PR.

Перед работой запроси у меня только отсутствующие данные, которые нельзя узнать локально:

- IP или hostname VPS, SSH user и способ входа;
- домен для HTTPS и подтверждение, что DNS уже указывает на VPS;
- нужно ли добавлять других разработчиков кроме `kernelsyv`.

Обязательные требования безопасности:

1. Никогда не показывай, не печатай, не коммить и не отправляй на VPS приватный ключ. Локальный ключ находится в `%APPDATA%\DDNet\kernelnet_developer.key`.
2. На VPS хранятся только публичные ключи и корневые сертификаты ролей из `developers.json`.
3. Клиент обязан проверять Ed25519-подпись локально, точное совпадение server address, client slot, name и clan, а также срок жизни не более 45 секунд.
4. Перед подписью challenge клиент обязан сверить все его поля со своим текущим состоянием.
5. Один identity key может подтверждать только один активный слот одновременно.
6. Сервис слушает только `127.0.0.1`; наружу он доступен через nginx с TLS. Не открывай порт 8088 в интернет.
7. Не заменяй проверку подписи доверием к имени, клану, цвету скина, SteamID или одному ответу VPS.

Порядок работы:

1. Проверь `git status`, текущую ветку и diff. Не затрагивай чужие изменения.
2. Сверь публичный ключ в `developer_identity.cpp` с `services/developer_identity/developers.json` и локальным приватным ключом, не выводя приватную часть.
3. Запусти Python unit tests сервиса и негативные тесты: неверная подпись, повтор challenge, другой IP, истёкшая сессия, перенос одного ключа на другой слот.
4. Собери Release-клиент. Устрани предупреждения и ошибки, связанные с новой системой.
5. Локально запусти сервис и проверь HTTP flow challenge -> sign -> activate -> sessions. Убедись, что после остановки heartbeat значок исчезает не позже TTL.
6. Разверни каталог `services/developer_identity` в `/opt/kernelnet-identity`, создай отдельного system user, venv и systemd unit.
7. Настрой nginx и Let's Encrypt, проверь `/healthz`, ограничения размера запроса и отсутствие публичного доступа к 8088.
8. Запиши HTTPS origin в `cl_zz_dev_identity_url` по умолчанию либо в поставляемый конфиг, как лучше соответствует текущей архитектуре проекта. На обычных клиентах publish должен оставаться выключенным.
9. На моём ноутбуке включи `cl_zz_dev_identity_publish 1` и проверь появление значка с двух экземпляров клиента или через интеграционный тест.
10. Обнови документацию, сделай целевые коммиты, push и draft PR в `kernelsyv/kernet`.

Готово только когда тесты проходят, Release собирается, HTTPS endpoint работает, приватный ключ остался только на ноутбуке, а в GitHub есть draft PR с описанием протокола, угроз и проверок.
